The streaming host, tightened up: only StrmLight can watch it, from StrmQt's own ports, with StrmLight's picture and sound set in StrmQt. Settings is reorganised, and the host no longer reaches into your desktop's display settings or system tray.

Update StrmQt before StrmLight: **StrmLight 0.9.1 needs StrmQt 0.9.1** and refuses an older one.

## After updating

If you use the streaming host, open Settings → StrmLight → Streaming host and press **Restart** once. That rewrites the host's files: it moves Sunshine to its new ports, keeps the host's display settings in its own folder, and takes its icon out of the tray. A StrmLight follows the host to the new ports by itself.

If your monitor's resolution, refresh rate or scale were reset while the 0.9.0 host was running, set them again in System Settings → Display & Monitor. The 0.9.0 host's KWin wrote its own screen into the desktop's display settings each time it started; 0.9.1's does not.

## What's new

### The streaming host

- **Only StrmLight can watch it.** Settings no longer has a PIN pad for a plain Moonlight, and any device StrmQt did not pair for a StrmLight is unpaired as soon as the host sees it. In the other direction, StrmQt tells a paired StrmLight which Sunshine is its own, and StrmLight 0.9.1 streams from no other: not a plain Sunshine, and not a Sunshine you run for games on the same computer.
- **Several TVs, one host.** Every StrmLight paired with the host can watch it, at the same time if you like: the same film in two rooms, or music through the house. Each StrmLight pairs with one StrmQt and forgets any other.
- **StrmQt's own ports, 8330–8356.** The host's Sunshine moves from 48989 (inside the range Linux lends to outgoing connections, which once kept it from starting) to a block of its own: 8330, 8335, 8336, 8344–8348 and 8356, with 8337 and 8338 left for the two remotes. StrmQt warns when Linux may lend those ports to something else.
- **Picture and sound for StrmLight, set in StrmQt.** Settings → StrmLight → Picture and sound: screen size, screen scale (the host's own KWin scale, as in System Settings' display page), frame rate, quality, codec (Automatic is HEVC wherever the TV decodes it) and stereo, 5.1 or 7.1 sound. StrmLight reads them before every stream. HDR is not offered: KWin's headless screen cannot be HDR yet.
- **The host keeps to itself.** Its KWin keeps its display settings in the host's own folder instead of the desktop's, and its Sunshine puts no icon in the system tray.

### Settings

- **YouTube, Mobile Web Remote and StrmLight** each have a section of their own. StrmLight's holds pairing, the streaming host, and picture and sound. The StrmQt running on the streaming host does not show it: the host is set up from the desktop StrmQt.

## On Ubuntu 24.04 and Debian 12

Every page and feature works on Qt 6.4. A few things are drawn slightly differently: icons, shadows and round masks use Qt's older effects module, the blurred backdrop behind Home and person pages has a different character, and the Crate music headings are narrower because Qt 6.4 cannot widen the display font.

## On Fedora

- The `.rpm` is tied to Fedora's exact Qt version. When Fedora updates Qt within a release, `dnf upgrade` holds that update back, or asks to remove StrmQt, until a StrmQt `.rpm` rebuilt for the new Qt ships. The Flatpak does not have this problem.
- HEVC and AAC need RPM Fusion's `ffmpeg` in place of Fedora's `ffmpeg-free`: `sudo dnf swap ffmpeg-free ffmpeg --allowerasing`.

## Known limitations

See [ARCHITECTURE.md §10](https://github.com/mpengellyCA/strmQt-linux/blob/v0.9.1/ARCHITECTURE.md#10-known-limitations). For the streaming host:

- **It has been used on one machine**, the development desktop, with one Fire TV. It has not yet run on a dedicated mini PC, and two TVs at once have not been tried.
- **TVs watching together are close, not synchronised.** Each TV shows the same live picture after its own network and decoder delay; nothing lines them up yet.
- **Starting at boot with nobody logged in is untested.**
- **Not in the Flatpak.** The streaming host needs systemd user services and KWin outside a sandbox.
- **StrmLight is installed by hand** (sideloaded); it is not in the Amazon or Google stores.

Everything else listed for 0.9.0 still applies.
