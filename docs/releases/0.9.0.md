StrmQt on a TV: a computer with no screen runs StrmQt for your Fire TV or Android TV, found by the TV on its own and paired with one four-digit code. The TV's own remote drives it.

## Install

Pick the file for your distro and install it from its local path, so the package manager pulls in the dependencies.

| Distro | File | Command |
|---|---|---|
| Ubuntu 24.04 LTS | `strmqt_0.9.0-1.ubuntu24.04_amd64.deb` | `sudo apt install ./strmqt_0.9.0-1.ubuntu24.04_amd64.deb` |
| Ubuntu 26.04 LTS | `strmqt_0.9.0-1.ubuntu26.04_amd64.deb` | `sudo apt install ./strmqt_0.9.0-1.ubuntu26.04_amd64.deb` |
| Debian 12 | `strmqt_0.9.0-1.deb12_amd64.deb` | `sudo apt install ./strmqt_0.9.0-1.deb12_amd64.deb` |
| Debian 13 | `strmqt_0.9.0-1.deb13_amd64.deb` | `sudo apt install ./strmqt_0.9.0-1.deb13_amd64.deb` |
| Fedora 43 | `strmqt-0.9.0-1.fc43.x86_64.rpm` | `sudo dnf install ./strmqt-0.9.0-1.fc43.x86_64.rpm` |
| Fedora 44 | `strmqt-0.9.0-1.fc44.x86_64.rpm` | `sudo dnf install ./strmqt-0.9.0-1.fc44.x86_64.rpm` |

A keyring is recommended but not required. Without one, StrmQt keeps your sign-in in a private vault file and tells you so.

## What's new

### StrmQt on a TV

- **Streaming host.** Settings → Web Remote → Streaming host sets up a StrmQt with no screen of its own, for a TV to watch: a hidden desktop running StrmQt full screen, and a Sunshine of its own streaming that desktop. It runs as two services of your user, with its own settings, certificate and ports, so a Sunshine you already use for games is left alone. StrmQt never installs or changes Sunshine; set-up says what is missing if it can't go ahead. A machine set up this way is meant to be a mini PC by the TV, with KDE's KWin and Sunshine installed.
- **StrmLight**, a Moonlight for Fire TV and Android TV made for StrmQt ([strmLight-android](https://github.com/mpengellyCA/strmLight-android)). It finds the streaming host on your network by itself and shows a four-digit code. Type that code once, in StrmQt's Settings → Web Remote → Pair a StrmLight or on your phone remote, and both the picture and the remote are paired. After that, opening StrmLight goes straight to StrmQt.
- **The TV's own remote drives StrmQt**: arrows, OK, Back, play and pause go to StrmQt directly rather than as keys through the stream.
- **Only StrmQt's sound goes to the TV.** The streaming host has a sound system of its own, with a virtual speaker and no sound card, so a game or a browser on the same computer stays on its own speakers and out of the stream. Set-up needs PipeWire and WirePlumber for it.
- **Paired devices, managed in Settings.** Settings lists every phone and StrmLight paired with the remote, and Moonlight devices paired with the stream, each with Remove.

### The phone remote

- **Pairing with a code instead of a PIN.** There is no standing PIN any more. Tap Pair on the phone, and StrmQt shows a four-digit code over whatever is on screen, a film included, for two minutes. Type it on the phone. A phone stays paired until you remove it in Settings, through restarts, sign-outs and profile switches.
- **The remote works signed out.** It drives the sign-in screen and the "Who's watching?" profile picker too. Your Emby sign-in and the remote's pairing are separate: signing in, switching profile or signing out never disconnects a phone.

### Everything else

- **On-screen keyboard.** Press OK in a text field with a gamepad, a TV remote or the phone remote, and a keyboard opens over the window. A real keyboard still types as before.
- **Home opens on a featured title** chosen from Continue Watching, Next Up and Latest, over its artwork, with Play or Resume and More info. **Logos** take the place of the title text on Home, details, series pages and the player wherever the server has one.
- **Gapless music with mpv.** The next track is loaded during the last 15 s of the one playing, so albums play without a gap.
- **Page transitions** follow the reduced-motion setting.
- **Subtitles on the VLC engine are drawn on Arch and Fedora.** The packages now depend on libVLC's text renderer (`vlc-plugin-freetype` on Arch, `vlc-plugins-extra` on Fedora); without it a subtitle loaded and was never seen.
- **Resuming on the VLC engine** no longer flashes the opening of the file before it jumps to where you left off.
- Many fixes to focus, live updates of watched and favourite state, the remote's security (a shared limit on wrong codes, certificate name checks) and mpv playback.

## On Ubuntu 24.04 and Debian 12

Every page and feature works on Qt 6.4. A few things are drawn slightly differently: icons, shadows and round masks use Qt's older effects module, the blurred backdrop behind Home and person pages has a different character, and the Crate music headings are narrower because Qt 6.4 cannot widen the display font.

## On Fedora

- The `.rpm` is tied to Fedora's exact Qt version. When Fedora updates Qt within a release, `dnf upgrade` holds that update back, or asks to remove StrmQt, until a StrmQt `.rpm` rebuilt for the new Qt ships. The Flatpak does not have this problem.
- HEVC and AAC need RPM Fusion's `ffmpeg` in place of Fedora's `ffmpeg-free`: `sudo dnf swap ffmpeg-free ffmpeg --allowerasing`.

## Known limitations

See [ARCHITECTURE.md §10](https://github.com/mpengellyCA/strmQt-linux/blob/v0.9.0/ARCHITECTURE.md#10-known-limitations). New in this release:

- **The streaming host has been used on one machine**, the development desktop, with one Fire TV. It has not yet run on a dedicated mini PC.
- **Starting at boot with nobody logged in is untested.** The streaming host needs your user's services running; whether its Emby sign-in is read without an unlocked keyring there has not been checked.
- **Not in the Flatpak.** The streaming host needs systemd user services and KWin outside a sandbox; the Flatpak says so instead of offering it.
- **StrmLight is installed by hand** (sideloaded) for now. It is not in the Amazon or Google stores.
- **The on-screen keyboard has not been used with a real gamepad or in YouTube Music's search box.**
- **Externally delivered subtitles stay off** unless `STRMQT_EXTERNAL_SUBTITLES=1` is set, until they are checked against a live server.

Carried over:

- **YouTube and YouTube Music are other people's pages.** StrmQt drives them with scripts that depend on how the two sites are built today; either can change without notice.
- **The copied YouTube Music sign-in expires** when Google says so; copy it again when it does.
- **The AppImage has no YouTube or YouTube Music yet.** Every other package does.
- **GNOME idle inhibition is untested.**
- **Offline source builds on Ubuntu 24.04 and Debian 12.** Building the `.deb` from source downloads one pinned, hash-checked SDL3 tarball, so an offline build will not work there. Installing the binary `.deb` is unaffected.
- The AppImage does not run on Debian 12 (glibc 2.36). Use the `.deb` or the Flatpak there.
